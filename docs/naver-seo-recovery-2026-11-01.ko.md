# 같이타 네이버 브랜드 검색 복구 작업

기준일: 2026-11-01 (한국 시간). 이 문서는 승인 요청서가 아닌 진단·수정·검증 기록이다.

## 확인한 현상과 근거

사용자 제보: Google에서는 ‘같이타’ 검색에 사이트가 상단에 보이지만, 네이버에서는 ‘가천대 같이타’로 검색해야 보인다. 10월 7일 Google Search Console 중복 페이지 알림 두 건을 첨부했다.

실제 브라우저 및 운영 HTTP 응답으로 확인했다. 검색 화면은 계정·시점에 따라 달라질 수 있으므로 전체 검색 순위로 일반화하지 않는다.

| 항목 | 측정 결과 |
| --- | --- |
| 네이버 ‘같이타’ | 확인한 첫 결과 화면에 gatita 도메인이 보이지 않음 |
| 네이버 ‘가천대 같이타’ | `/about`이 노출됨 |
| 네이버 `site:gatita.kro.kr` | 홈, `/about`, `/faq`, `/privacy`, `/terms` 총 5개 확인 |

| 사이트맵 | `sitemap.xml` 기존 제출 확인 (2026-06-23 21:56) |
| 사이트 진단 | 10월 30일 업데이트, 최근 90일: 색인 5, 수집 제한 0, 색인 제외 0, SEO 진단 0 |

따라서 네이버 전체 색인 삭제나 robots 차단 문제는 확인되지 않았다. Google 과거 경고 역시 현재 진행 중인 홈 미색인의 증거가 아니다. 10월 7일 당시 Google 선택 표준 URL은 확인하지 못했다.

네이버 수집 현황은 11월 1일 업데이트지만 차트의 정확한 수집 완료·제한 건수를 추출하지 못했다. 위 진단 화면의 수집 제한 0과 구분한다. 검색어별 순위·패널티·하락 원인은 확인되지 않았으며 추정으로 확정하지 않는다. Core Web Vitals와 실제 기기 UX는 이번 점검 범위에 포함하지 않았다.

## 확인된 기술 문제와 수정

1. 이전 운영 주소 `gatitagachon.vercel.app`이 공식 주소와 같은 HTML을 200으로 제공했다. canonical은 있었지만 두 호스트가 독립적으로 열렸다. 이 **정확한 호스트의 안내 페이지 4개(`/about`, `/faq`, `/privacy`, `/terms`)만** 공식 주소 `https://gatita.kro.kr`로 308 영구 이동한다. 경로와 쿼리를 보존하고, 프리뷰 호스트는 이동시키지 않는다. 초기 SEO 수정에서는 `/`도 이동했으나, 후속 PWA 점검에서 오래된 시작 주소와 OAuth 복귀가 다른 호스트로 넘어가 인증 쿠키를 사용할 수 없게 되는 경로를 확인해 제외했다. 루트는 200으로 제공하면서 공식 주소 canonical을 유지한다. 앱 화면, API, OAuth 콜백, 서비스워커 및 정적 자산에도 호스트 이동을 적용하지 않는다. [후속 PWA 수정 기록](pwa-auth-navigation-fix-2026-11-01.ko.md)을 참고한다.
2. `/map`, `/rooms`, `/rooms/[id]`, `/routes`, `/settings`, `/admin` 및 하위 관리 화면이 홈 제목을 상속하고 검색 제외 지시가 없었다. 각 경로의 서버 레이아웃에서 `noindex, follow`를 제공한다. robots.txt로 수집 자체를 막지 않아 검색엔진이 지시를 읽을 수 있게 한다. 앱 경로에 홈 canonical을 추가하지 않는다. 이는 개인정보 접근 제어를 대체하지 않는다.
3. 홈의 HTML 제목과 OG 제목이 달랐고 설명에는 브랜드 이름이 없었다. 기존 제목 ‘같이타 - 가천대 택시 동승 플랫폼’을 유지하고 HTML·OG·Twitter 제목/설명을 공통 상수로 통일했다. 설명은 ‘같이타는’으로 시작하여 실제 서비스 범위를 설명한다. WebSite 구조화 데이터도 같은 설명을 사용한다.

공개 홈·소개·FAQ·약관·개인정보처리방침의 개별 canonical과 사이트맵을 유지한다. 화면 디자인, 로그인·채팅·정산 코드는 수정하지 않는다. 이전 호스트의 안내 페이지로 접속한 방문자는 공식 호스트로 이동하며, 앱 진입 및 인증 복귀에 쓰이는 루트는 기존 호스트에 유지한다. 기존 설치 앱의 별도 호스트 상태를 자동 이전하지는 않는다. 코드 리뷰에서 전체 경로 호스트 이동이 기존 API·OAuth·PWA 요청을 깨뜨릴 수 있다는 지적을 반영했고, 후속 점검에서 루트 예외를 추가했다.

위 수정은 중복·색인 신호를 정리하는 작업이다. 현재 네이버에 색인된 앱 내부 페이지는 확인되지 않았으므로 내부 경로의 중복 신호가 순위 하락을 일으켰다고 주장하지 않는다. 메타 설명 통일이나 영구 이동만으로 ‘같이타’ 순위 회복을 보장할 수 없다.

## 검증

- 변경 전 운영 서버에 HTTP 회귀 검사를 실행해 앱 경로 7개 `noindex` 누락, 이전 호스트의 공개 페이지 200 응답, 홈 메타 불일치를 재현했다.
- 기존 테스트: 283개 통과, 실패 0.
- `npm run build`: 프로덕션 빌드 및 타입 검사 통과.
- HTTP 검사: `SEO_BASE_URL=http://localhost:3317 SEO_CHECK_ALIAS=local npm run test:seo` 29개 통과. 실제 빌드 HTML의 공개 canonical·색인 허용, 앱 경로/하위 경로의 검색 제외, 사이트맵, 구조화 데이터, 호스트별 이동 및 프리뷰 호스트 접근성을 검증했다. 로컬 호스트 분기는 Host 헤더를 무시할 수 있는 fetch 대신 Node HTTP 클라이언트로 검사했다.
- 운영 검증: `SEO_BASE_URL=https://gatita.kro.kr SEO_CHECK_ALIAS=1 npm run test:seo`.
- 코드 리뷰의 호환성 지적을 반영한 뒤 재리뷰에서 남은 차단 문제 없음. 실제 로그인·물리 기기 PWA 세션 이전은 검증하지 않았다.

## 재수집과 추적

배포 후 홈·소개·FAQ의 운영 응답을 확인한 뒤 네이버 서치어드바이저에서 재수집한다. 이미 등록된 사이트맵은 삭제하지 않는다. 수집 요청 접수는 실제 재수집·재색인·검색 순위 회복과 다르다.

재수집 이후 네이버에서 ‘같이타’와 ‘가천대 같이타’, 도메인 제한 검색, 홈/소개 페이지의 노출·클릭을 비교한다. Google은 현재 홈이 정상 색인이므로 과거 경고만으로 불필요한 삭제나 재등록을 하지 않는다.

기존 홈에는 화면에 표시되지 않는 서비스 설명 블록(`HomeSeoContent`, `sr-only`)이 있다. 관련 서비스 설명이라는 점에서 이를 자동으로 스팸이라고 단정할 수 없으나, 홈의 실제 초기 화면이 로딩 문구 중심이라는 제한이 있다. 추가 콘텐츠·화면 변경을 하려면 사용자의 디자인 검토 선호에 맞춰 별도 시안을 먼저 검토한다. 이번 작업에서 숨겨진 키워드나 콘텐츠를 추가하지 않았다.
