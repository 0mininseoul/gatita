# PWA 인증 이동 회귀 수정

## 범위와 결정

조사에서 재현한 기존 호스트의 인증 복귀 이동과 서비스 워커의 인증 콜백 대체 문제를 수정한다. 제보자가 전달한 파란 오류 화면의 원인으로 확정한 작업은 아니다.

- `gatitagachon.vercel.app`의 루트 `/`는 오래된 PWA 시작 주소이자 OAuth 기본 복귀 주소이므로 같은 호스트에서 제공한다. `auth`, `auth_error`, 초대 복귀 쿼리가 있어도 호스트를 바꾸지 않는다.
- 기존 호스트의 루트 HTML은 `https://gatita.kro.kr/` canonical을 유지한다. 소개·FAQ·개인정보처리방침·약관 4개 경로의 기존 영구 이동도 유지한다. 이 방식은 기존 로그인 쿠키를 다른 호스트로 옮길 필요가 없다.
- 서비스 워커의 `/auth/` GET은 API 요청과 마찬가지로 네트워크 응답만 사용한다. 네트워크가 실패하면 실패를 보존하며 홈 HTML이나 과거 callback 캐시를 반환하지 않는다. 일반 앱 화면의 오프라인 캐시 대체는 유지한다.
- 캐시 이름은 유지한다. 워커 파일의 내용 변경으로 업데이트를 배포하며, 인증 처리 중인 창을 불필요하게 강제 새로고침하지 않는다. 새 워커 활성화 후 동작을 실제 Chromium에서 검사한다.

## 실행 순서와 수용 기준

1. 기존 전체 테스트와 프로덕션 빌드를 실행해 기준 상태를 확인한다.
2. 실제 서비스 워커 코드를 실행하는 회귀 테스트에서 오프라인 callback이 캐시된 홈/동일 callback으로 대체되는 실패를 확인한다. 로컬 프로덕션 HTTP 검사에서 기존 루트 및 인증 쿼리의 308 이동도 실패로 확인한다.
3. 두 동작만 수정한다. 기존 SEO 검사에 루트의 호스트 유지와 canonical 검증을 포함하고 관련 설명을 갱신한다.
4. 전체 테스트·프로덕션 빌드·HTTP 검사를 통과시킨다. 기존 브라우저의 워커를 새 코드로 갱신한 뒤 오프라인 callback은 네트워크 실패, 일반 지도는 캐시 반환, 온라인 callback은 같은 호스트 복귀를 확인한다.
5. 변경 diff를 검토하고 결과를 기록한다. 실제 Google 계정의 로그인 완료와 Android 실기기 검증은 수행한 것으로 간주하지 않는다.

## 변경 전 확인

- 기존 테스트 283개와 프로덕션 빌드 통과.
- 새 서비스 워커 테스트 5개 중 2개가 예상대로 실패: 캐시된 홈 또는 같은 callback 페이지가 반환되어 네트워크 실패가 가려짐.
- 새 HTTP 검사 4개가 예상대로 실패: 기존 호스트의 루트 및 인증/초대 복귀 쿼리가 모두 308으로 다른 호스트로 이동함.

## 수정 후 검증

- 전체 테스트 **288/288 통과**. 추가한 서비스 워커 행동 테스트 5개를 포함한다.
- 프로덕션 빌드 통과. 빌드에 포함된 lint 및 TypeScript 검사도 통과했다.
- `SEO_BASE_URL=http://127.0.0.1:4317 SEO_CHECK_ALIAS=local npm run test:seo`: **32/32 통과**. 기존 호스트 루트의 인증/초대 쿼리 4가지 모두 200과 공식 canonical을 확인했다. 안내 페이지 4개 영구 이동과 앱·API·프리뷰 예외도 유지됐다.
- 같은 격리 Chromium과 기존 `gatita-v1.0.4` 캐시를 유지한 채, 이전 워커의 오프라인 callback은 200 캐시 응답이었고 새 코드가 활성화된 뒤에는 `net::ERR_FAILED`로 보존됐다. 앱의 일반 `/map` 오프라인 탐색은 계속 서비스 워커 캐시에서 200으로 응답했다.
- 온라인에서 코드 없는 callback은 같은 origin의 루트로 돌아가 `auth_error`를 보존했다. 실제 Google 계정으로 OAuth를 완료하거나 Android 실기기에서 재현한 검증은 아니다.
- 독립 코드 리뷰에서 수정이 필요한 추가 결함은 발견되지 않았고, 리뷰어가 서비스 워커 테스트 5개와 diff 검사를 별도로 통과시켰다.
- 조사 제보 화면과의 인과관계는 미확정이며, 이 수정은 별도로 확인한 두 결함을 대상으로 한다.
