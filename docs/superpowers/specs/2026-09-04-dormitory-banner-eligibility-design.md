# 기숙사 동행 요청 배너 노출 조건 수정

## 상태

승인됨. 구현 전 문서 검토 대기.

## 목표

기숙사 동행 요청 배너를 기숙사생으로 명시 설정한 사용자에게만 보여주고, 출발지의 방향에
맞는 질문을 사용한다.

## 사용자 동작

- `is_dormitory_resident === true`인 사용자만 동행 요청 배너를 볼 수 있다.
- `is_dormitory_resident === false`이거나 아직 응답하지 않은 `null` 사용자는 배너를 볼 수 없다.
- 기존 재고 조건은 그대로 유지한다. 즉, 기숙사생이더라도 해당 출발지에 입장 가능한 관련
  방이 있으면 배너를 보여주지 않는다.
- 가천대역 1번 출구와 가천대학교 정문에서는 `혹시 기숙사 가시나요?`를 표시한다.
- 제2기숙사에서는 `혹시 역으로 가시나요?`를 표시한다.
- 배너 클릭 뒤 요청 시트의 안내 문구, 목적지 규칙, 시간 선택, 방 생성과 푸시 동작은 변경하지
  않는다.

## 구현 설계

`HomeClient`가 이미 `/api/profile/me`에서 받은 비공개 프로필의
`is_dormitory_resident` 값을 보유하므로 추가 네트워크 요청이나 스키마 변경 없이 이 값을
`CampusRouteMap`에 boolean 권한으로 전달한다. 지도는 다음 두 조건을 모두 만족할 때만 배너를
렌더링하고 노출 이벤트를 기록한다.

1. 현재 사용자가 기숙사생으로 명시 설정되어 있다.
2. 기존 `getDormitoryRequestAvailability`가 배너를 허용한다.

문구는 선택된 출발지가 `제2기숙사`인지에 따라 지도 컴포넌트에서 결정한다. 비기숙사생에게는
배너 DOM 자체를 렌더링하지 않으며, 배너 노출·클릭 분석 이벤트도 발생하지 않는다.

## 오류 및 상태 변경

- 프로필 로딩 중이거나 값이 없으면 안전한 기본값인 비노출로 처리한다.
- 설정에서 기숙사생 여부를 변경하고 지도로 돌아오면 기존 프로필 로딩 흐름이 최신 값을
  반영한다.
- 서버의 방 생성 검증과 푸시 수신자 검증은 기존대로 유지한다. 이번 변경은 배너 접근성만
  좁힌다.

## 테스트

- 기숙사생이면서 기존 재고 조건을 만족할 때만 배너가 렌더링되는지 검증한다.
- 비기숙사생과 미응답 사용자에게 배너 및 노출 이벤트가 나타나지 않는지 검증한다.
- 역·정문 출발 문구와 제2기숙사 출발 문구가 각각 정확한지 검증한다.
- 기존 목적지·빈 방·요청 생성 테스트와 전체 테스트, ESLint, TypeScript, 프로덕션 빌드를
  통과시킨다.
